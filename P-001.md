# P-001A — LAUNCH PROTECTION

# EXECUTION SPEC

# TARGET: CODING AGENT

Status: READY FOR IMPLEMENTATION

Priority: P0

Objective:

Make Atlas safe, reliable, and deployable for the first 100 active users.

This is NOT a feature sprint.

This is a production hardening sprint.

Do not introduce new product features.

Do not modify research behavior.

Do not redesign architecture.

Do not add MCPs.

Do not add multi-agent systems.

Do not add exports.

Do not add dashboards.

Do not add workspaces.

Only implement launch protection.

---

# SUCCESS CRITERIA

Atlas is considered launch-ready when:

✓ Authenticated users are rate limited

✓ Health endpoint verifies dependencies

✓ Memory creation cannot silently fail

✓ Users receive meaningful error messages

✓ Critical failures are logged

✓ Existing features continue functioning

---

# SCOPE

Implement:

1. Rate Limiting

2. Deep Health Checks

3. Persistent Memory Jobs

4. Error Surfacing

No other work is allowed.

---

# P-001A.1 RATE LIMITING

## GOAL

Prevent abuse of expensive endpoints.

Protect:

* Groq
* Tavily
* Firecrawl
* Pinecone

---

## AUTH STRATEGY

Already implemented:

Clerk

Use authenticated user ID.

---

## LIMITS

Research:

5 requests/minute

---

Comparison:

3 requests/minute

---

Memory APIs:

20 requests/minute

---

Health APIs:

Unlimited

---

## IMPLEMENTATION

Backend only.

Preferred library:

slowapi

---

Create:

middleware/rate_limit.py

---

Apply limits to:

POST /research

POST /compare

GET /memory

POST /memory/promote

---

## RESPONSE

429

Example:

{
"error": {
"code": "RATE_LIMIT_EXCEEDED",
"message": "Rate limit exceeded. Please try again later."
}
}

---

## REQUIREMENTS

Rate limiting must be user-based.

Not IP-based.

Authenticated Clerk user id is the key.

---

# P-001A.2 DEEP HEALTH CHECKS

## GOAL

Atlas must know if dependencies are healthy.

---

## PUBLIC ENDPOINT

GET /health

Response:

{
"status": "healthy"
}

or

{
"status": "degraded"
}

---

No internal details exposed.

---

## ADMIN ENDPOINT

GET /admin/health

Requires authentication.

Admin access only.

---

## CHECKS REQUIRED

Postgres

Pinecone

Groq

Tavily

---

## RESPONSE

{
"status": "healthy",
"services": {
"postgres": true,
"pinecone": true,
"groq": true,
"tavily": true
}
}

---

## DEGRADED EXAMPLE

{
"status": "degraded",
"services": {
"postgres": true,
"pinecone": false,
"groq": true,
"tavily": true
}
}

---

## IMPLEMENTATION

Create:

services/health_service.py

routes/admin_health.py

---

Health checks must have timeout protection.

No dependency check should block more than 2 seconds.

---

# P-001A.3 PERSISTENT MEMORY JOBS

## GOAL

Memory creation must never silently disappear.

Current problem:

Research Complete

↓

Memory Create

↓

Failure

↓

Lost Forever

This is unacceptable.

---

## DESIGN

Create durable memory job tracking.

---

## NEW TABLE

memory_jobs

Columns:

id

user_id

memory_id

status

attempt_count

last_error

created_at

updated_at

---

## VALID STATUS

queued

running

completed

failed

---

## FLOW

Research Complete

↓

Memory Summary Generated

↓

Create memory_jobs row

↓

queued

↓

Process

↓

completed

---

## FAILURE FLOW

Research Complete

↓

Memory Create

↓

Failure

↓

failed

↓

stored

---

No failure may disappear.

---

## RETRIES

Maximum:

3

---

Backoff:

Attempt 1

↓

Immediate

Attempt 2

↓

30 seconds

Attempt 3

↓

120 seconds

---

## IMPLEMENTATION

Create:

services/memory_job_service.py

models/memory_job.py

schemas/memory_job.py

---

## IMPORTANT

No Redis.

No Celery.

No external queue.

Use Postgres only.

Keep implementation simple.

---

# P-001A.4 ERROR SURFACING

## GOAL

Users must know when Atlas is degraded.

Atlas should never silently fail.

---

## ERROR TYPES

MemoryUnavailable

PineconeUnavailable

TavilyUnavailable

ProviderFallback

HealthDegraded

---

## FRONTEND

Create:

components/system/SystemStatusBanner.tsx

---

Display non-blocking banners.

Examples:

Memory system temporarily unavailable.

Research memory may not be used for this request.

---

Search provider unavailable.

Evidence collection may be reduced.

---

Primary model unavailable.

Fallback provider activated.

---

## RESPONSE FORMAT

Backend standard:

{
"error": {
"code": "PINECONE_UNAVAILABLE",
"message": "Memory retrieval is temporarily unavailable."
}
}

---

## REQUIREMENT

All backend exceptions must be mapped.

No raw tracebacks.

No generic 500 responses.
