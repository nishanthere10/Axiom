# P-001 — Engineering Workspace Specification

**Status:** Draft v1.0

**Depends On**

* RFC-001 — Atlas Product Constitution
* RFC-002 — Atlas Evolution Blueprint
---

# 1. Purpose

This specification defines the complete user experience of Atlas.

Unlike RFC-001 and RFC-002, which define product philosophy and architecture, this document defines **how users interact with Atlas**.

The Engineering Workspace is the primary experience of the platform.

Every capability should feel like part of one continuous engineering workflow.

---

# 2. Goals

The Engineering Workspace should:

* Reduce context switching
* Organize engineering work naturally
* Keep repository context always available
* Preserve engineering thinking
* Make previous decisions discoverable
* Make starting new work effortless

---

# 3. User Journey

The canonical user journey is:

```text
Create Workspace
        │
Connect GitHub
        │
Repository Intelligence Generated
        │
Create Initiative
        │
Start Exploration
        │
Research
        │
Decision
        │
Knowledge Updated
        │
Workspace Intelligence Improves
```

This flow should remain the default experience.

---

# 4. Navigation Philosophy

Atlas is **Workspace First**.

Users never navigate around features.

Users navigate around engineering work.

Navigation hierarchy:

```text
Workspace
        │
Overview
        │
Initiatives
        │
Repository
        │
Knowledge
        │
Decisions
        │
Settings
```

---

# 5. Workspace Dashboard

The Workspace Dashboard becomes the homepage.

Purpose:

Provide a complete understanding of the workspace in less than one minute.

Sections:

## Workspace Summary

Displays:

* Workspace name
* Members
* Connected repositories
* Active initiatives

---

## Active Initiatives

Shows:

* Current initiatives
* Status
* Last activity

Primary CTA:

> New Initiative

---

## Repository Intelligence

Displays:

* Languages
* Frameworks
* Databases
* Infrastructure
* AI-generated architecture summary

Repository Intelligence should always be visible.

---

## Recent Decisions

Displays:

* Latest decisions
* Status
* Confidence
* Linked initiative

---

## Knowledge Summary

Displays:

* Recent knowledge updates
* Frequently referenced decisions
* Repository insights

---

## Recent Activity

Timeline of:

* Research
* Decisions
* Repository syncs
* Knowledge updates

---

# 6. Sidebar Navigation

```text
Workspace

├── Overview

├── Initiatives

├── Repository

├── Knowledge

├── Decisions

└── Settings
```

Rules:

No feature-first navigation.

Everything belongs to the workspace.

---

# 7. Initiative Experience

An Initiative represents a single engineering objective.

Example:

Authentication Migration

Clicking an Initiative opens:

```text
Overview

Exploration

Research

Decisions

Repository Context

Knowledge

History
```

Everything related to that objective lives inside the Initiative.

---

# 8. Exploration Experience

Every Initiative automatically creates an Exploration.

Purpose:

Capture engineering thinking before formal research.

Exploration supports:

* Problem statement
* Goals
* Assumptions
* Constraints
* Open questions
* Initial ideas

Primary CTA:

> Start Research

---

# 9. Research Experience

Research validates an Exploration.

Inputs:

* Exploration
* Repository Intelligence
* Workspace Knowledge
* Previous Decisions
* Web Search

Outputs:

* Recommendations
* Trade-offs
* Alternatives
* Evidence
* Confidence

Research is always associated with an Initiative.

Standalone research is not supported.

---

# 10. Decision Experience

Research can produce one or more Decisions.

Each Decision contains:

* Recommendation
* Summary
* Evidence
* Confidence
* Alternatives
* References
* Status

Decision lifecycle:

```text
Draft

↓

Accepted

↓

Implemented
```

Rejected decisions remain searchable.

---

# 11. Repository Experience

Repository is not a file browser.

Repository is an engineering intelligence view.

Displays:

* Technology stack
* Frameworks
* Architecture
* Deployment
* Dependencies
* Repository health
* Connected repositories

Repository Intelligence should be reusable throughout Atlas.

---

# 12. Knowledge Experience

Knowledge is automatically generated.

Users do not manually maintain it.

Knowledge contains:

* Engineering insights
* Historical research
* Previous decisions
* Repository understanding
* Frequently referenced context

Knowledge continuously evolves.

---

# 13. Search Experience

One global search.

Searches:

* Initiatives
* Research
* Decisions
* Knowledge
* Repository Intelligence

Users should never wonder where information lives.

---

# 14. Quick Actions

Workspace Dashboard always exposes:

* New Initiative
* Start Research
* Sync Repository
* Export Decision
* Search Workspace

These actions should be accessible in one click.

---

Connect GitHub

Create first Initiative

↓

Step 4

---

# 16. Permissions

Workspace Owner

* Full access

Workspace Member

* Create initiatives
* Research
* Decisions

Future roles may be added without changing navigation.

---

# 17. UX Principles

Every screen should answer:

What am I working on?

Why am I here?

What should I do next?

What has already been decided?

Navigation should never require more than three clicks to reach any engineering artifact.

---

# 18. Design Principles

Workspace First

Initiative First

Context Before Intelligence

Knowledge Over Conversation

Repository Aware

Decisions Over Chat History

Reduce Context Switching

Progressive Disclosure

The interface should reveal complexity only when needed.

---

# 19. Success Metrics

The workspace succeeds when users:

* Start work from an Initiative rather than a blank chat.
* Reuse previous decisions instead of repeating research.
* Understand repository context before asking questions.
* Return to Atlas to continue engineering work.
* Trust Atlas as the source of engineering truth.

---

# 20. Acceptance Criteria

The Engineering Workspace is complete when:

✓ Every engineering activity belongs to an Initiative.

✓ Repository Intelligence is available throughout the workspace.

✓ Research cannot exist without context.

✓ Decisions are linked to their engineering objective.

✓ Knowledge updates automatically.

✓ Users naturally think in terms of engineering work rather than isolated AI conversations.

---

# Closing Statement

The Engineering Workspace is the heart of Atlas.

It transforms Atlas from a collection of AI-powered capabilities into a coherent environment where engineering teams can explore ideas, conduct research, make technical decisions, and build lasting organizational knowledge.

Every future feature should strengthen the Engineering Workspace rather than compete with it.

The workspace is no longer a container for features.

It is the environment where engineering thinking lives.
